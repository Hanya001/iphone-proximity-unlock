# iPhone Unlock

一个面向 Ubuntu / GNOME 的原生小工具：在图形界面配对并选择 iPhone，调整信号门槛，然后在锁屏页面点击 **用 iPhone 解锁**。仅在你点击按钮或按 **Ctrl + Alt + U** 后验证，不会因手机靠近而自动解锁。

当前版本：**0.1.2**。许可证：**MIT**。界面为简体中文。

[版本记录](CHANGELOG.md) · [测试与兼容性](TESTING.md)

## 功能

- GTK 4 / libadwaita 设置窗口，可从应用列表启动。
- 扫描蓝牙设备、核对配对码、确认或取消配对。
- 选择已绑定的手机，连接测试，观察实时连接 RSSI。
- 默认只检测已有连接，不主动重连，避免验证手机时主动连接音频服务。
- 可选非音频主动验证：手机断线后也能验证，不请求手机的音频服务。
- 调整信号门槛和启用状态，保存后立即作用于下次解锁。
- 锁屏时钟页和密码页均有按钮，显示验证状态。
- 单次信号验证；验证失败继续使用原来的密码。
- 配置仅保存在本机；源代码不包含任何用户的手机地址。

## 环境

目前支持 **GNOME Shell 50**，在 Ubuntu 26.04 / Wayland 上验证。扩展使用 GNOME 的内部锁屏接口，因此不能直接保证其他 GNOME 版本或其他桌面环境兼容。

依赖使用发行版软件包安装，无需 pip 或 root 后台服务：

```bash
sudo -A apt install python3 python3-gi gir1.2-gtk-4.0 gir1.2-adw-1 bluez gnome-shell
```

`hcitool` 需要可用，用来读取已连接手机的 RSSI。安装器会检查 GNOME 版本、GTK 和蓝牙工具。该命令的 `-A` 使用本机配置的图形 sudo 助手；其他机器也可以按其常规方式安装依赖。

## 安装与使用

在解压的项目目录内运行，**不要使用 sudo**：

```bash
python3 install.py install
```

1. 在应用列表打开 **iPhone Unlock**。
2. 在手机上打开“设置 → 蓝牙”，在窗口内点击“扫描设备”。
3. 选择手机并点击“配对”，核对电脑与手机上的配对码，双方确认。
4. 选择连接模式：需要手机断线后仍能验证时，打开“允许主动重连”；只使用已有连接时保持关闭。
5. 点击“连接并测试”或“测试已有连接”，观察信号并设置门槛；默认值为 `-45`，需按本机环境调整。
6. 打开“允许 iPhone 解锁”，点击“保存设置”。
7. 首次安装或更新扩展代码后，保存工作并注销、重新登录一次。
8. 按 `Super + L` 锁屏，点击“用 iPhone 解锁”。

修改设备、阈值或启用状态后只需保存，不用再次注销。设置窗口关闭后不会后台扫描；验证进程只在点击锁屏按钮时运行。

### 连接模式

| 模式 | 手机未连接时 | 适合场景 |
| --- | --- | --- |
| 关闭“允许主动重连” | 不建立连接，验证失败 | 手机已有连接，只希望读取信号 |
| 打开“允许主动重连” | 尝试建立临时非音频通道并验证 | 手机开关蓝牙或离开后返回，仍希望点击按钮解锁 |

新配置默认关闭“允许主动重连”：解锁和 GUI 信号测试都只检查已有连接。手机没有连接时验证失败，不会执行连接命令，也不主动断开任何现有连接；此时可使用密码解锁。升级会保留已保存的开关；旧配置缺少该字段时按关闭处理。

如需断线后仍能验证，可在 GUI 打开“允许主动重连”并保存。0.1.2 起，主动验证使用临时的 SDP / L2CAP 非音频通道，并要求已配对设备完成认证和 16 字节密钥加密，不再调用通用 `Connect()` 或 `bluetoothctl connect`。读取信号及发送解锁请求后关闭该通道，不主动断开其他连接；连接超时最多约 6 秒。验证失败不会回退到音频连接。

测试按钮会相应变成“连接并测试”。GUI 测试使用窗口当前选择的模式；锁屏解锁使用已保存的模式。

在当前测试环境中，已验证断线后的非音频重连、认证加密和 RSSI 读取，音频列表未出现 iPhone 音频设备；用户实际使用耳机播放并解锁后，确认此前的音频抢占问题已解决。这是一台设备上的验证结果，不能保证系统、手机或其他应用在所有环境下都不调整音频连接。具体记录见[测试与兼容性](TESTING.md)。

配对是显式操作，仍需与手机建立连接。仅检测模式不能阻止系统、手机或其他应用自行重连，也不会撤销已经建立的音频连接。

关闭“允许 iPhone 解锁”并保存，会立即禁止手机解锁；锁屏按钮仍可见，密码入口保留。也可停用整个扩展：

```bash
gnome-extensions disable iphone-unlock@local
```

## 原理与限制

通过配置中选定的蓝牙地址定位手机，确认已配对并已绑定，再按选择的模式验证连接并读取一次 RSSI。主动模式要求非音频通道的安全级别至少为 `BT_SECURITY_HIGH`，且加密密钥长度至少为 16 字节；仅检测模式读取现有连接，不额外建立认证通道。只有连接有效且信号达到门槛，才请求 systemd-logind 解锁当前用户的本地活动图形会话。配置缺失、损坏、停用，或手机无法验证时均不会解锁。

RSSI 是粗略远近指标，不是精确测距。`hcitool rssi` 在经典蓝牙连接上的值不能直接等同于其他设备的 dBm 阈值；应在本机实测后选择门槛。人体、口袋、墙壁、设备功率变化都可能影响结果。

**这是一种便利性解锁方式，不是强身份认证或抗中继的距离证明。手机在附近时，其他能点击按钮的人也可能解锁电脑。** 不用于高安全要求的工作站。仅处理已经登录的桌面锁屏，不处理开机登录或磁盘解密，不修改 PAM，不保存系统密码或蓝牙配对密钥。

程序不读取、保存或代填锁屏密码；它通过当前用户的会话解锁接口工作，不是新增一个 PAM 密码认证模块。配置保存的是设备地址、名称、启用状态、连接模式和 RSSI 门槛。

蓝牙配对密钥由系统 BlueZ 管理。配对时显示的确认码不是电脑锁屏密码。卸载工具不会删除系统已有的配对。

## 配置与诊断

配置：`~/.config/iphone-unlock/config.json`，遵循 `XDG_CONFIG_HOME`。原子写入，文件权限为 `0600`。

程序：`~/.local/lib/iphone-proximity-unlock/`。

扩展：`~/.local/share/gnome-shell/extensions/iphone-unlock@local/`，遵循 `XDG_DATA_HOME`。

```bash
python3 ~/.local/lib/iphone-proximity-unlock/gui.py
python3 ~/.local/lib/iphone-proximity-unlock/watcher.py --check
gnome-extensions info iphone-unlock@local
journalctl --user -b --no-pager | rg 'iPhone Unlock'
```

故障排查：

- 看不到手机：让 iPhone 停留在蓝牙设置页，确认电脑蓝牙开启，再扫描。
- 手机开关蓝牙后识别不到：打开蓝牙、已配对不等于已连接。仅检测模式不会重连；如需断线后验证，打开“允许主动重连”并保存。
- 耳机播放被打断：先确认使用 0.1.2 或更新版本。早期版本的通用连接可能涉及音频服务，单独将 iPhone 的音频配置设为 `off` 不能保证阻止下次连接。更新后关闭并重新打开设置窗口，再测试耳机播放期间点击锁屏按钮；如仍有问题，记录设备型号和连接切换日志。
- 连接成功但读不到信号：确认 `hcitool` 可用及当前用户有相应访问权限；不会因此绕过信号验证。
- `--check` 显示未连接：该命令只读检查，不会主动验证；主动模式的临时通道结束后，手机再次显示未连接不一定是故障，可在 GUI 点击“连接并测试”。
- 更新后没有按钮：注销并重新登录，再查看扩展状态。
- 点击后验证失败：在 GUI 中连接测试，检查信号门槛；必要时使用密码。

## 卸载

```bash
python3 install.py uninstall
```

默认保留配置；彻底删除本工具配置：

```bash
python3 install.py uninstall --purge
```
